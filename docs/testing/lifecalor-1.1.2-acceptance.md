# LifeCalor 1.1.2 开发与验收记录

核对日期为 2026-11-06。本轮基于 `main` 的 `a3bf420`，验收的源码与应用版本均为 1.1.2。

## 已完成的更新

- 修复 Qt 测试窗口与异步回调的生命周期。关闭主窗时协作取消任务，异步等待处理、缓存读写和维护线程，以及本工具的预览池完成，再解绑 GUI 日志。控件与 Matplotlib 对象由其自身所有权机制清理。
- 在“高级操作 → 时空卷积”加入 HW/THW 数据选择、预设与逐层自定义核、显式归一化、边界与偏移、小 ROI 后台预览、可取消的有界执行和历史/导出。CPU 工作内存估算包含 SciPy 原生 offsets 表。
- 修复 CUDA 双指数寿命步长过冲与 CPU STFT 双精度中间舍入。
- 对 AVI 报告帧数与实际解码帧数分别记录，短解码时显示导入提示。
- 根据当前实测，将 Auto 保守设为 CPU，保留显式 GPU 选择。

## 自动回归

开启 `LIFECALOR_RUN_CUDA_TESTS=1`、将 `CUPY_CACHE_DIR` 指向项目内缓存后，完整发现并运行 **437 项，全部通过，0 跳过，进程退出码 0**。最终源码验证用时约 17.03 秒，包含目标 GPU 数值、实际 worker 取消和受控 OOM 缩块检查。

稳定性修复过程中，默认环境的全量测试已连续三轮正常退出。新增回归还覆盖忙碌线程关闭、无 parent 的缓存线程、先关对话框后等待旧预览，以及长密卷积核在低预算下提前拒绝。

最终默认模式完整发现 437 项，其中 9 项目标 GPU 用例按开关跳过，其余通过，进程退出码 0。本次用时约 8.50 秒。

Qt 测试会销毁各自创建的顶层窗口。原先的 `close()` 只隐藏窗口，残留对象可能在后续样式刷新或解释器退出时触发原生访问冲突。计算设置页的线程完成回调已改为 QObject 绑定槽。真实 Windows 源码窗口显示后 0ms 和 200ms 关闭均正常退出。

本轮曾尝试在生产退出时遍历删除 Qt 顶层窗口，实际 EXE 验证捕获到 `shared QObject was deleted directly`。该方案已撤回。最终生产实现仅管理自己的任务、线程和日志，Qt 内部 popup、菜单等对象保持其原有共享所有权，显式测试窗口销毁由测试夹具负责。

## 打包与验证入口

构建环境使用 `requirements-build.txt`，GPU 开发依赖在 `requirements-cuda.txt`。默认完整版使用 `core/LifeCalor.spec`，CPU 精简版使用 `core/LifeCalor-CPU.spec`。构建出的文件分别为 `dist/LifeCalor.exe` 与 `dist/LifeCalor-CPU.exe`。

完整版收集 CUDA Toolkit 的 DLL 与 JIT 头文件，运行钩子设置包内 CUDA 路径。二进制依赖扫描产生的根目录 CUDA DLL 副本会被移除，以保留一致的 `bin/x64` 布局，保证 CuPy 从 NVRTC 位置推导出包内根目录。

验证脚本会让新工作进程仅使用 EXE 内的模块路径，避免继承源码虚拟环境而误判独立运行能力。CUDA 版执行自检与 STFT 数值对照，CPU 版检查 CUDA 模块排除。随后通过正常窗口入口启动，并向同一进程树的主窗口发送关闭事件，检查退出码。

```powershell
.\.venv\Scripts\python.exe tools/verify_package.py dist/LifeCalor-CPU.exe --backend cpu
.\.venv\Scripts\python.exe tools/verify_package.py dist/LifeCalor.exe --backend gpu
```

最终两个 EXE 内嵌版本均为 `1.1.2`，验证结果如下。文件大小和 SHA256 保存在[打包验收原始记录](package-2026-11-06.json)。

| 产物 | 包内计算验证 | 主窗口验证 | 进程退出码 |
| --- | --- | --- | --- |
| `LifeCalor-CPU.exe` | CUDA 不可用，符合 CPU 精简版预期 | 显示后正常关闭 | 0 |
| `LifeCalor.exe` | RTX 5070 Ti 自检、STFT 和单/双指数拟合通过 | 显示后正常关闭 | 0 |
| `LifeCalor.exe` 立即关闭 | 单独核对启动与关闭的生命周期 | 主窗显示后无额外延时即关闭 | 0 |

完整版冻结 worker 的 STFT 最大绝对误差为 `5.96e-8`。已知单指数寿命 `2.5` 拟合为 `2.5000000000008966`，双指数 `(2.5, 12)` 拟合为 `(2.4999999999559486, 11.999999999346791)`。这些结果来自仅使用包内模块的新工作进程。

## 剩余验收

- 真实寿命分析需要有明确时间轴的衰减序列。当前单页 TIFF 用于二维图像验证，寿命的已知参数合成测试已通过。
- CUDA 卷积原型完成局部数值对照，卷积工作台的正式执行目前使用 CPU。完整 CUDA 资源规划、worker 注册与工具工作流仍需后续适配。
- 当前性能记录覆盖 small/medium。更大规模的设备收益和显存峰值需要另行实测，基准中的设备端峰值与分阶段耗时字段仍为 `null`。
