# LifeCalor 1.1 计算加速验收清单

## 当前支持边界

- STFT：有界 CPU 已完成；可选 CUDA 后端已接入隔离进程，等待目标 NVIDIA 电脑验证。
- CWT：有界 CPU 已完成；CUDA 尚未开放，避免改变 PyWavelets 的小波核、尺度或边界语义。
- EM 预处理：有界 CPU 已完成，保持前 N 帧精确中位数背景和 float32 兼容输出。
- 单指数寿命热图：有界单进程/多进程 CPU 已完成；GPU 尚未开放。
- 双指数：选区拟合可用；热图没有确定的双寿命归约定义，仍明确拒绝。
- Auto：没有同设备、同算法、同精度的可信性能档案时选择 CPU。

## CPU 基础回归

1. 在没有安装 CuPy 或 CUDA 不可用的电脑启动软件，导入、显示和 CPU 计算应正常。
2. 分别以 float32、float64 和可用的复数 STFT 数据对比原有结果，检查 shape、时间轴、频率轴、dtype 和幅值。
3. 对同一数据执行单尺度和多尺度 CWT，检查时间长度、尺度/频率 metadata、whole_mean 和画布显示。
4. 对 EM 预处理比较背景图与结果，确认使用前 N 帧的精确中位数，不是各块中位数的平均。
5. 对单指数寿命热图分别使用单进程、多进程和预/后卷积，检查寿命图、R² 图及块接缝。
6. 将缓存阈值调低，确认 STFT、CWT 和预处理结果以 NPY 缓存引用进入历史，并可显示、恢复和导出。

## NVIDIA 实机验收

1. 打开“编辑 → 计算与加速 → 硬件状态”，先点“CUDA 快速自检”。记录显卡型号、显存、驱动、CUDA/CuPy 版本和自检结果。
2. 使用小型确定性数据分别运行 STFT CPU/GPU，保持参数和精度完全相同；比较 shape、时间轴、频率轴、选频索引及数值误差。
3. 使用日常真实 float32 数据测 CPU/GPU 冷启动与热运行，总耗时应包括读取、传输、计算、回传和落盘。
4. 再验证双精度或 complex128，但不预设消费级显卡一定快于 CPU。
5. 运行大数据时观察峰值 RAM、显存、缓存磁盘占用与 GUI 响应；输出不得完整驻留内存时应直接落盘。
6. 在上传、计算和写盘阶段分别取消一次；任务应进入“正在取消/已取消”，不增加历史，不留下 `.compute_tasks` 半成品，后续任务仍可运行。
7. 制造显存不足：GPU 最多缩块重试 3 次；允许回退时清理半成品并从 CPU 重跑，严格 GPU 时只报一次结构化错误。

## Auto 性能档案门槛

只有同一设备、算法版本、dtype、典型 shape 和数据驻留状态下，GPU 端到端中位耗时预计至少提升 1.3 倍且节约至少 0.5 秒，才考虑让 Auto 选择 GPU。在形成并持久化该性能档案前，Auto 保持 CPU。

## 发布前检查

- CPU-only 环境不在启动路径导入 CuPy。
- PyInstaller 入口保留 `multiprocessing.freeze_support()`，GPU 与寿命多进程可正常 spawn。
- 目标 CUDA 包、驱动和 CuPy 组合单独记录；不把 Compute Capability 12.0 误写成 CUDA Toolkit 12.0。
- 完整自动化测试、真实数据烟测、缓存恢复、历史、画布和导出均通过后，再更新版本号与更新日志。
