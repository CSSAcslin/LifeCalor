## 1. 设计决定

### 1.1 这次看起来应该是什么样

主推新主题“石墨深色”：中性炭灰的工作区、清晰灰白文字、克制的薄荷绿操作强调，配以蓝色信息、琥珀警告和珊瑚红错误。它应当像成熟的数据分析工作台，而不是游戏启动器。

同时提供“清爽浅色”：保留现有浅色使用习惯，改为中性灰白底与深绿色主操作。两个主题共享组件结构和视觉规则，而不是各自维护一套不同界面。

共同改变：

- 大面积绿色边框、绿色正文、渐变状态栏改为中性表面、细分隔与必要的强调色。
- 工具图标延续 LifeCalor 现有形状语言，适配深浅背景，不重新学习图标含义。
- 分区依靠位置、标题、留白和表面明度，不继续叠加边框和浮动卡片。
- 表格、菜单、输入、任务状态、计算器、图表和启动页形成一个完整系统。
- 保留科研内容的多色表达；界面不把所有线条、图例或伪彩统一染成绿色。

不承诺深色主题适合所有人或具有护眼医疗效果，用户始终可以切回浅色。

### 1.2 主题入口与默认行为

- 在现有“编辑”菜单新增“界面主题”子菜单，使用互斥 QAction：“石墨深色”“清爽浅色”。
- 选择后即时应用，不重启、不重新打开数据、不弹“保存成功”提示；持久化到同一 QSettings 的 `appearance/theme`，值为 `dark/light`。
- 没有设置的老用户和首次安装均默认浅色，避免升级时擅自改变操作环境；用户主动选一次深色后，后续启动从启动页开始就是深色。
- 本轮不加“跟随系统”、定时切换、任意自定义主色、密度切换、动画或独立外观设置大窗口。
- 所有主题拥有相同控件尺寸和字体，不因切主题改变窗口大小、画布分区、列宽或光标焦点。
- 已打开和后来新开的 Qt 窗口均应用当前主题；暂未显示的重型图表可在再次显示前更新，不能闪出旧白底。
- 本轮主题失败回退已知可用的浅色，并通过现有日志/错误处理报告一次；不得以报错循环阻止用户启动。

## 2. 范围与不变量

本轮仅改变界面外观及其必要的资源管理、状态映射与输出外观隔离。

必须保持：

- 原始数组、ProcessedData、metadata、缓存引用、dtype、shape、THW 轴语义不变。
- 像素实际值、当前帧、LUT/colormap、levels、归一化范围、ROI、画笔自定义色不变。
- 四象限、停靠/浮动、聚焦、画布稳定 ID、布局持久化和用户缩放不变。
- 数据名称、三个表情标签、多选、筛选、计算器 A/B/C 绑定与表达式不变。
- 错误仍走已有 diagnostics；warning 不升级为弹窗，不能为改颜色另建异常总线。
- UI 主题不写进数据历史、不触发缓存落盘、不使算法重跑。

明确不做：

- MainWindow 瘦身指标、全仓库清理、数据存储改造或功能重排。
- 改用 Qt6、Electron、WebEngine 重写桌面 UI，或引入第三方整套主题框架。
- 重写系统标题栏和窗口拖动；不使用未公开 Windows 接口强行统一非客户区颜色。
- 批量反色图像、调整科研 colormap、对画布套透明遮罩、给数据导出加主题滤镜。
- 新建输出格式、曲线分析算法和并行任务调度器。

### 4.3 可读性要求

- 正文及重要辅助文字按至少 4.5:1 检查；键盘焦点、必要控件边界和图标按至少 3:1 检查。细装饰分隔线不冒充唯一的控件边界。
- 此处把 WCAG 数值作为桌面 UI 的工程目标，不宣称完成了全套无障碍认证。[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 上述色值的 sRGB 相对亮度计算：正文/面板约为深色 13.24:1、浅色 14.81:1；辅助文字约 7.91:1、6.44:1；主按钮字/底约 8.76:1、6.90:1。这里只是颜色计算，不代表 Qt 实机渲染已验证。
- 实现阶段测试包含 normal、hover、pressed、checked、focus、selected、selected-inactive、disabled，以及错误输入；不要只测试默认截图。
- 关键数据值不使用极细字重或半透明正文。错误信息支持换行/复制，Tooltip 使用不透明背景，避免压在图像上难读。

## 5. 组件视觉规范

### 5.1 布局、间距与字体

- 保留现有区域位置与比例；工作区是连续分区，不增加大标题、欢迎页、装饰卡片或额外侧栏。
- 通用间距采用 4/8/12/16 逻辑像素；一般控件圆角 4，对话框内独立工具最大 6；表格单元格不画圆角小卡片。
- 已有普通按钮/输入的高度以约 30 逻辑像素为基线，用字体度量设置最小高度，不固定到中文或高 DPI 下裁字。
- 画布图标保持当前 36 逻辑像素体系，命中区域至少约 40×40；不要为“现代感”把所有工具缩小。非画布紧凑工具可用 16/20 图标、28/32 命中区。
- 普通行高以 28 左右为基线，含多行摘要的行按内容增高；不取消现有完整 Tooltip。
- 正文继续使用 app_bootstrap 的至少 10pt 字体；段落标题 10/11pt 加粗，启动页品牌标题可 20pt。不得随窗口宽度缩小字体。
- 中文继承已可用的应用字体/系统回退，公式和控制台用 Consolas 等宽族配中文回退；表情仅在标签区域使用 Segoe UI Emoji 回退。
- 保留小数、科学计数法、负号、微秒符号和单位，字体变化不改字符串与数值精度。
- 不重复乘设备像素比，不重新引入 dialog 子控件固定 px 小字体。新增 UI 字间距为 0；不触碰用户自定义图像标尺字体。

### 5.2 工具栏和图标

- 保留现有按钮排列、作用、Tooltip 与快捷键。描边/填色改为中性前景和少量薄荷色，不把每个图标放在实心绿方块里。
- 新旧图标都检查 16/24/36 尺寸可辨认性，尤其是布局、浮动、聚焦、关闭、添加、删除、导出和树展开箭头。
- 深浅版本尽量共享 SVG 几何，用明确的主题色槽生成或维护成对资源；不对整个图标位图反色。
- UI 图标可以换色；colormap 色条、用户颜色 swatch、原图缩略图、应用品牌图标及表情不统一染色。
- QIcon 的 Normal、Active、Selected、Disabled 与切换主题后的实例都要处理；不能只更新未来新创建的按钮。
- 资源/缓存 key 包含主题、尺寸、DPR 和必要状态。Qt 图像对象只在 GUI 线程创建；不在每次 paintEvent 重新解析所有 SVG。
- 布局工具继续独立于绘图工具互斥组，打开其菜单不能重置当前工具、ROI 或伪彩。
- 树节点展开/折叠改用清楚的 chevron，与添加/删除动作图区分；不改变节点行为和操作列。

### 5.3 输入与操作状态

- 普通按钮用中性底色与清楚边界；一个操作区域只有真正执行该区域主流程的按钮使用 accent 实心底，不把所有导出/刷新按钮都设为主按钮。
- 按钮的悬停、按下、聚焦不改变 padding、border 总厚度或最小尺寸。预留焦点边界，禁止文字位移和界面跳动。
- 输入框、SpinBox、ComboBox、下拉弹层、Checkbox 三态、RadioButton、Slider 手柄、Tab、Splitter、ScrollBar 都有深浅样式。
- readonly 与 disabled 不同：只读数据可复制且文字清晰；禁用操作弱化但仍能辨认。
- 错误输入保留输入内容，以错误边界和相邻错误文字提示；不为每次输入错误弹窗。
- 进度条使用稳定高度。百分比优先放在紧邻的独立文本区，避免同一串文字横跨浅色进度块和深色轨道而一半看不清；保留底栏约 50% 的既有定位，不让长任务名挤动它。

### 5.4 历史、计算器、任务与辅助窗口

- 历史多选高亮必须整行连续，包含树枝区域；表情标签只保留自身颜色，不套三层标签背景。
- 计算器按键分区、输入、数据槽、失败步骤和结果预览位置不变。语法色使用主题的 info/number/function 角色，而非在两种主题里复用暗紫/暗蓝字。
- 计算器检验通过/警告/失败使用本方案状态配对；表格 item 自己设置的背景、前景也要同步，不能只改外层 QLabel。
- 任务面板与控制台保持原停靠位置。日志正文改为中性可读色，不延续荧光绿大段文字；本轮不为日志着色重写日志解析或重建全部历史日志。
- 若现有结构化状态可直接映射颜色就复用；没有级别格式元数据的历史日志保持正文，不逐行猜测“ERROR”重处理。
- 帮助、更新说明、数据详情、错误详情、缓存设置、标签窗口都在覆盖范围内，不能只完成主窗口。
- 系统原生文件对话框、颜色选择器和 Windows 标题栏可跟随系统外观，不强行替换成自制无边框窗口；把这一例外写入交付说明。

## 6. 科研显示与导出的隔离

### 6.1 主题可以改什么

- pyqtgraph：PlotWidget/ViewBox 外部背景、坐标轴与刻度、网格、图例文字/底色、悬浮标签、交互手柄等 UI 外观。
- Matplotlib：Figure/axes 外观、spines、ticks、labels、legend、annotation 背景以及明确归属自动样式的线条。
- 时间轴：背景、刻度文字、游标/手柄的视觉角色，不修改时间单位格式和缩放。
- OpenGL 切片器：外围控件、标注文字、坐标线、视图背景等界面外观；不重建 mesh、texture、渲染窗口或上下文。
- QGraphicsView：viewport/scene 外围底色、空画布状态与控件，不变换图片颜色。

### 6.2 主题不能改什么

- 不更改 imageItem 图像、QImage/QPixmap 内容、显示帧缓存 key、LUT、levels、alpha、gamma、科学 colormap 或数值归一化。
- 不调用 display_image、update_plot、重新加载预览、创建新 Data/ProcessedData、重新求直方图来实现切主题。
- 不对大数组执行 copy、deepcopy、np.asarray、min/max、全量统计或再次物化。
- 不改变 ROI 数据和用户明确指定的线色、散点色、画笔色、色图参数。
- 不修改 Matplotlib 全局 `rcParams` 为 `dark_background`；不依赖 `pg.setConfigOption` 一次调用就能更新已创建的对象。[pyqtgraph 全局配置说明](https://pyqtgraph.readthedocs.io/en/pyqtgraph-0.12.2/config_options.html)

### 6.3 曲线的自动颜色与用户颜色

- 仅由 App 自动分配的分析曲线颜色参与深浅主题映射。为这种曲线保存轻量 `color_role/color_index`；用户手动指定后标记为 custom，不按颜色字符串相等猜测归属。
- 同一曲线在深浅主题中保持对应色相与图例身份，不重新打乱颜色顺序。已知固定语义的拟合线/参考线保持语义角色。
- 建议自动曲线前六色：深色 `#70B7FF, #F0B45A, #70D3B1, #ED92BD, #D7D775, #B1A0ED`；浅色 `#246EB0, #A6580C, #177750, #AC3E78, #746407, #7053AE`。
- 直方图柱子配同色轮廓和适度透明填色；不能因图背景改变就重新统计 bins/counts。
- 无法确定归属的已有自定义颜色按 custom 保留；不偷偷“优化”用户颜色。默认曲线应在对应背景可辨认，图例、线型和标记辅助区分，不能承诺仅靠六种颜色对所有色觉都足够。

### 6.4 默认科研图表导出

必须区分两类：

| 导出内容 | 主题影响 |
| --- | --- |
| 原始/处理数据、NPY/CSV、画布图像及 TIFF/PNG/AVI/GIF | 无主题影响；保留现有是否导出伪彩、原始值等语义 |
| 带坐标、图例、标题的分析图表 | 提供“论文白底（默认）/当前显示”外观，白底默认与 UI 当前主题无关 |

图表导出规则：

- “论文白底”使用白底、深色轴字、适合白底的自动曲线色；colormap、用户自定曲线色、数据、单位、坐标范围、拟合结果不变。
- “当前显示”保留当前图表外观；主题不自动把旧的白底导出设置改成深色。
- 接入 Matplotlib 的现有图像导出入口以及 pyqtgraph 图表右键导出入口，不能只覆盖其中一个。选项只出现在图表导出中，不污染原图/视频导出参数。
- 不能只在 `savefig` 中加白色 facecolor 而保留白色轴字，也不能导出白底配几乎不可见的浅色自动线条。
- 实现使用现有图表/artist 的轻量外观快照，在受控导出上下文中应用输出样式并在 finally 精确恢复；不 deepcopy 整张 Figure，不重算数据、不调用 UI 全局主题切换。
- 若现有 exporter 需要一个预览视图，则该视图独立持有外观参数，只引用当前已绘制数据；不另行恢复整个数据源。具体对接以本机库 API 为准，不升级依赖解决。
- 与活图表共享对象的实际导出阶段暂停该图表的外观更新，将主题变更合并为一次导出后的应用；不停止算法任务、不阻塞用户看其他数据。
- 取消或失败后原图表的颜色、图例、范围、当前选项卡都恢复；下一次画布渲染和输出不能残留临时白底配置。

## 7. 最小而完整的主题实现

### 7.1 模块建议

```text
core/appearance/
    __init__.py
    tokens.py          # light/dark 配色与只读角色，轻量且不引入 NumPy/绘图库
    manager.py         # QSettings、QPalette、QSS、themeChanged、切换保护
    widgets.qss        # 一套 Qt 样式模板，Python 代入主题值
    plots.py           # pyqtgraph/Matplotlib 的有界外观适配与导出样式
```

图标逻辑优先放入 manager 或现有资源辅助代码，复杂后才拆 `icons.py`；富文本适配也不必一开始另建一个大型框架。

- 一个 ThemeManager 由 QApplication 持有。普通 Qt 控件使用应用 QPalette + 全局 QSS 继承，不逐个订阅。
- QPalette 明确设置 Active、Inactive、Disabled 的 Window、WindowText、Base、AlternateBase、Text、Button、ButtonText、Highlight、HighlightedText、ToolTip 等角色。
- QSS 只使用当前 PyQt5 支持的属性和伪状态；Python 展开 token，不把浏览器 CSS variables、filter、transition 当成 Qt 支持的语法。
- 专用 QPainter/plot/富文本控件提供小型 `apply_theme(tokens)`；使用有生命周期的连接/弱引用注册，窗口销毁后解除，避免重复切换积累回调。
- themeChanged 只传主题/角色数据；主线程更新 GUI 对象，不在主题线程操作 QPixmap、QIcon 或图表。
- 背景工作任务与主题系统无耦合。切换不清空、重新创建或遍历 Data.history，也不写 manifest。
- 只保留单个主题请求应用过程；连续选择相同主题无工作量，快速来回切换合并为最新请求，避免重复 repolish 所有控件。

### 7.2 启动与存储

- 保持 configure_high_dpi 在 QApplication 之前，configure_application 确定组织/应用名之后再读 QSettings。
- 初始化轻量主题管理器、应用 palette/QSS、设置图标，然后创建并显示 splash；主题加载不能导入 MainWindow、NumPy、Matplotlib、pyqtgraph 或扫描全部字体。
- 将现有字体注册与主题加载解耦；保留早期日志可记录主题缺失，不延后启动页到重型模块加载之后。
- 配置缺失使用 light；未知 theme id 或资源异常回退内置 light/Fusion palette 并记录原因，不覆盖其他设置。
- 正常切换在基础主题与专用适配成功后再持久化。个别组件失败要恢复旧外观并报告一次，不留下“设置里是深色、半个界面还是浅色”的成功状态。
- 外观资源使用当前资源根路径/qrc 机制兼容源码启动与打包，不从工作目录拼相对文件。
- Qt 原生文件对话框和系统标题栏的例外不算适配失败，不为其触发重试。

### 7.3 局部样式收束规则

将现有颜色按三类处理：

1. **固定 UI 装饰色**：迁移到 token；去掉强制白底和会覆盖全局主题的局部 setStyleSheet。
2. **状态语义色**：通过 `semanticState`、`uiRole` 等动态属性及对应角色映射；属性变化时只刷新该控件。
3. **科学/用户选择的颜色**：保留，例如画笔、色图、swatch、图像内容，不能全局替换。

其他要求：

- QGroupBoxCreator 保留业务调用，只改为设置分组角色；弱化多层边框，不改变控件父子关系。
- DataFilterControls 继承主题输入样式；历史/标签窗口当前已验收的功能与选中规则不回退。
- 整理 style.qss 中重复和无效规则，包括会改变控件尺寸的焦点样式、白色 branch、旧注释块；仅限本轮主题相关内容。
- 旧 style.qss 不能与新模板同时作为两套权威样式。确认所有入口/测试/资源引用迁移后删除或转为有说明的兼容入口。
- QTextBrowser 的主题使用 Qt 富文本支持的 CSS 子集，并处理已有内联颜色；不依赖网页 JS、CSS variables 或 QSS 自动覆盖 HTML。
- 帮助页正文与结构不重写；通过主题化公共样式和少量类名替换固定装饰色。切换保留当前页、滚动位置与选择，不重新请求远程更新内容。
- 对强制黑字的 Tooltip/富文本段落作同样处理，不只检查纯文本 QLabel。
