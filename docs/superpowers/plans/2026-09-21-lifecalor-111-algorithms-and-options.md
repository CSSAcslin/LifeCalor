## 1. 版本目标与不变量

用户应能通过统一的“选项”设置默认 CPU/GPU、精度和资源策略；现有算法入口提交任务后，由统一执行层处理分块、计算、取消、错误和结果保存。新增算法不再修改中央分发中的专用 STFT 分支。

本版必须同时交付三条主线：

1. 通用但有限的算法注册与执行接口，支持时间序列、邻域计算、多结果输出。
2. 真正执行在 CUDA 上的 CWT 与单/双指数寿命拟合，并保持可核验的 CPU 对照。
3. 用“选项”替换空的“主窗口”菜单，将首选项归入同一个分类设置窗口。

保持以下行为不变：

- 默认精度继续“兼容现有”；日常 float32 正常支持，float64/complex128 不是新默认。CPU/GPU 切换、OOM 重试均不得暗中降低精度。
- 原始数据不变；结果继续使用 ProcessedData、ArrayRef、已有历史/缓存/显示/导出链路。
- 名称、标签、筛选、多选、已保留缓存和目录切换保护不回退。
- 普通画布、ROI、计算器和切片器的操作流程不重写；新算法不改变 THW 含义或当前帧。
- error 汇总弹窗，warning 不弹窗，所有级别记录日志；禁止按 traceback 每行弹窗。
- 不以 MainWindow 行数为目标，不重扫已修复的 token 等旧问题，不收录实验数据和打包产物。

不在本版建设：第三方算法插件市场、任意 Python 自动 GPU 化、多 GPU 联合计算、任务 DAG 编辑器、所有旧线程任意并发、完整卷积核三维编辑器、全体缓存格式迁移。

## 3. 通用算法入口

### 3.1 统一描述与注册

扩展 `core/compute/`，不要另起一套计算系统。现有 `AlgorithmRegistry.py` 只是名称到函数的轻量映射，应提供兼容适配并整合职责，不能留下两份不同的能力真相。

建议一个不可变 AlgorithmSpec，至少声明：

- 稳定 algorithm_id / contract_version、名称、参数模式及校验器。
- 允许的轴、输入类型、实数/复数规则、精度解析器。
- 具名输出：shape、dtype、轴、单位、语义和主结果字段；支持一个主数组加多个结果数组。
- 执行模式、分块规划器、边界规则、工作区估算；不在 UI 中另写一份估算。
- CPU/CUDA handler、能力谓词、自检与正确性测试版本；按算法注册而非按菜单文字路由。
- 结果 metadata 构造器；明确继承和失效字段，不直接展开所有父 out_processed。

设置中的算法列表、可用后端、参数校验和 worker 分发从注册表取得。保留当前算法 ID 与设置键；旧存档通过版本化适配，不改名导致首选项丢失。

仅加载应用自带、明确注册的 handler；不要通过 IPC 接受任意模块路径、表达式或可执行 pickle 回调。“通用”不是远程执行任意代码。

### 3.2 一个提交入口，不是一个万能内核

建议 `submit_compute(request)` 对接已有 TaskCoordinator。UI、anchor 或其他算法入口只负责准备请求和展示结果，不各自创建进程、循环分块、判断 OOM。

请求冻结 task_id、attempt_id、算法参数、数据版本/只读引用、轴和单位、后端偏好、精度策略、资源预算与输出目录。小核/窗口数组也要独立只读，不能只冻结字典而允许内含数组被修改。

执行分为四个可组合步骤：验证/计划 → 块执行 → 归约或多结果汇总 → 完成提交。复杂算法可提供自己的阶段实现，但必须复用同一取消、资源、进度、诊断和提交协议。不要强迫非分块算法伪装成普通逐像素函数。

### 3.3 本版实际支持的执行模式

| 模式 | 用途 | 约束 |
| --- | --- | --- |
| 独立时间曲线 | 寿命、已验证的完整时间 STFT/CWT 路径 | 对每批空间像素保留足够 T；不能随意把寿命曲线分段拟合后平均 |
| 时间窗口/邻域块 | CWT 时间分段、固定时空卷积、预卷积 | 显式读入边界外邻域并裁剪，仅在整个源数据边界填充 |
| 多结果与归约 | 寿命/R²/质量标记，CWT 选尺度归约 | 逐块写出/合并，统一完成标记，不先组装巨大结果树 |

STFT 在迁移时可以先保留已验证的完整时间策略；不得仅因接口升级改变窗口中心或 time_point。新增窗口策略只有通过独立边界测试才启用。

定义 BlockPlan：核心输出区域、输入读取区域、每轴前/后 halo、全局坐标、边界填充和有效输出裁剪。支持非对称 halo，为 1.1.2 的偶数核、偏移核、因果时间核做好准备。

空间三维体数据不一定是 THW 视频；本版算法逐项声明所支持轴，不因 ndim==3 擅自赋予 T。彩色/额外通道也不得被无提示混进时间轴。

### 3.4 资源、进程与数据安全

- 扩展现有 planner/executor/worker/io。块预算覆盖 host、VRAM、输入输出、halo、FFT 工作区、求解器状态、固定传输缓冲与队列；CPU 并行预算是所有在途块的总额，不是每进程各领一份全局预算。
- 对总量/字节偏移使用 Python 整数；Qt 进度继续使用归一化范围。巨大数组的规划测试不分配真实 TB 文件。
- 引用获得任务租约；运行/排队中的数据不能因历史删除、目录切换或清缓存失效。任务期间可切换焦点，不引用后来变化的当前数据。
- CUDA 进程按 algorithm_id 分发受信任 handler；消息携带 task_id、attempt_id、block_id。不要继续每加一个算法就改 if/elif 中央分支。
- 大数组不经 GUI 线程序列化或传输；优先引用/有界共享缓冲，数据与控制消息分离，避免发送块时无法收到取消。
- 默认一个 GPU 执行一个重任务；保留 task_id 协议供未来并发。只迁移本版算法，不宣称所有老 worker 已支持并发。
- 内核/迭代/读写间隙协作取消；不可中断的 CUDA 调用超时可终止本任务隔离进程，GUI 不调用阻塞 join/wait。取消不触发 CPU 重跑。
- OOM 只缩块/减在途量，有限重试后依设置回退 CPU；不改精度、尺度、采样率、损失函数或容差。数值与代码错误不通过回退掩盖。
- 多结果临时文件完成后以一个清单/完成标记提交；仅注册一次历史。失败/取消不留可恢复半成品，旧 attempt 的迟到消息不能提交。
- 原有结果落盘阈值继续可设置，不能把 512 MB 硬编码为所有工作内存上限；必要流式结果直接写现有缓存系统，不进行二次整组落盘。

## 4. CWT GPU：本版必须交付

### 4.1 科学参考

以当前项目安装版本的 PyWavelets 和 `core/compute/backends/cpu.py:cwt_block_cpu` 为参考，锁定版本、积分核采样精度与公式。当前 1.1.0 已采用：

```text
result[t, h, w] = mean_s(2 * abs(coeff[s, t, h, w]) / sqrt(scale[s]))
```

该公式本版不再重新决定。目标频率到 scales、采样率、频率返回值、时间轴和输出 dtype 必须与 CPU 路径一致。

PyWavelets 的 CWT 有特定的积分小波、尺度重采样、差分和截边约定；不能用 CuPy 中同名函数或另一种 Morlet 定义直接替代。[官方 CWT 文档](https://pywavelets.readthedocs.io/en/latest/ref/cwt.html)、[官方实现](https://github.com/PyWavelets/pywt/blob/main/pywt/_cwt.py)

### 4.2 实现路径

1. 在 CPU 生成小波离散核与轴 metadata；按 wavelet、scale、采样精度、dtype 和库版本缓存小核，受容量约束。
2. 在 GPU 批量执行卷积/FFT、差分、截边、幅值和尺度归约。FFT 优先调用 CuPy/cuFFT，不手写 FFT；复数小波的共轭、系数符号和相位按参考核逐项验证。
3. 沿像素、尺度分批，必要时沿 T 分段。halo 由实际离散核及差分操作决定，不凭经验固定为窗口半长；内部块不重复进行全局边界补零。
4. 每批尺度立即累计归约，避免 S×T×H×W 完整体；CPU 基线也逐尺度分批，修正目前块内仍一次构造全部尺度系数的内存峰值，保持精度契约。
5. 对大尺度、长支持核估算 halo 放大率。最小合法块也不可容纳时明确说明资源不足，依设置回退 CPU，而不是减少 scales。
6. 输入 float32/float64/complex64/complex128 均有对照；兼容策略保持当前已确认 dtype，其他策略显式解析计算、归约与输出精度。NaN/Inf 行为单独冻结并测试，不能因 FFT 将局部无效值扩散到整条曲线后仍声称与 CPU 一致，也不能自动填零或丢帧。

本版 GPU 支持覆盖当前 UI 已提供的 `cmor1-1.0`、`cmor1.5-1.0`、`cmor3-3`、`cmor8-3`、`cgau8`、`mexh`、`morl`。规范化现有 `cmor8-3 ` 的尾空格而不改变小波含义。参数化的新小波不自动标记已验证。

信号计算与质量分析共享核与参数验证，但注册不同的输出描述：信号计算输出归约后的 THW，质量分析保留现有尺度/频率与时间二维谱及绘图 metadata，不能把它错误归约成一条曲线。单条质量曲线在 Auto 下通常继续 CPU，但显式 GPU 选择应按能力表执行或明确拒绝，不能悄悄忽略设置。

### 4.3 UI 与状态

移除“CWT CUDA 尚未完成”的静态提示，改为来自能力表的动态说明。将“算法已实现”“设备自检通过”“该配置验证通过”“预计有加速收益”分开；不再仅凭 GPU 可用就由 Auto 一律选择 GPU。

## 5. 寿命拟合 GPU：单/双指数均纳入本版

### 5.1 先冻结拟合契约

单指数 `A * exp(-t/tau) + C`；双指数 `A1 * exp(-t/tau1) + A2 * exp(-t/tau2) + C`。必须保留当前有效 CPU 路径的信号正负处理、峰位筛选、从头/峰后起算、时间单位、初值、求解约束、tau/R² 后筛选和失败状态。

注意区分“求解器参数边界”和用户的 `tau_range` 后筛选，二者目前不是同一机制，不可为实现 GPU 擅自合并。

实施前用确定性测试显式化 SciPy 的现有默认求解方法、停止容差与评估预算。带 bounds 的 curve_fit 默认使用 TRF，而不是无约束 LM；不同求解器结果不能假定等价。[SciPy curve_fit](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.html)

现有双指数下界 `[0, 0, 10, 10, -inf]` 对 A2 和 tau2 带有数值约束，可能使默认初值不可行。先做 CPU 复现：有效老参数行为保持；将无效初值调整到可行域须明确记录并同时用于 CPU/GPU，不能单边改 bounds。不能因为改成两个对称分量“更合理”就静默改变科学模型。

### 5.2 双指数结果不再强行压成一个寿命

本版明确采用具名多结果：`tau1_map`、`tau2_map`、`amplitude1_map`、`amplitude2_map`、`baseline_map`、`r_squared_map`、`fit_status`。按需附加残差/迭代次数；数组可分别落盘，不创建 T×H×W 拟合曲线体。

- 标签使用“模型分量 1/2”，不擅自称为快/慢分量；存在非对称约束时不随意交换标签。
- 主显示字段默认 tau1_map，结果视图提供切换 tau2/R² 等具名结果；处理/导出选择要记录实际字段，不用菜单显示一个分量却导出另一个。
- 旧单指数仍是一个主寿命图及 R²；不改变旧结果字段含义。双指数旧选区曲线继续可绘制，新热图用明确的算法/结果版本接入。
- 不默认平均两个 tau，不引入未经确认的“有效寿命”公式。以后若增加归约，应作为用户明确选择的新结果。
- 原始拟合参数和质量状态保留；无效显示可兼容原来的 0，但不得把拟合失败、筛选排除与真实零值混为同一状态。

### 5.3 GPU 求解器选择

默认寿命仍为 float64。Gpufit 官方 Python 接口文档使用 float32，因此不能直接装一个现成 wheel 就替换当前默认拟合；即便采用自定义构建，也必须证明模型、约束和双精度绑定符合要求。[Gpufit Python 接口](https://gpufit.readthedocs.io/en/latest/bindings.html)

本版基准实施路线：使用现有 CuPy 后端承载**限定单/双指数的批量受界约束非线性最小二乘**，优先复用经验证的求解实现或审阅过的参考算法，底层矩阵分解使用成熟数值库。不构建任意模型求解平台。

前置原型必须先证明以下事项，再连接 GUI：

1. 残差、模型及解析 Jacobian 与 CPU 有限差分核验一致；每条曲线独立阻尼/信赖域、有效样本、收敛状态和迭代次数。
2. 用稳定的受界约束信赖域或经验证的阻尼求解；不能仅把无约束更新 clip 到边界就称为完成。小线性系统通过分解求解，不显式求逆；避免病态正规方程导致伪收敛。
3. 参数缩放、可行步、停止准则、奇异/病态检测有确定行为。不同求解器可产生不同迭代轨迹，但科学输出须达到第 10 节一致性要求。
4. 每批曲线的模型/残差/Jacobian 与迭代主体确实在 GPU 上，不能只在 GPU 算指数、每次迭代把整批拉回 CPU 调 curve_fit。
5. 时间曲线按像素批驻留。峰后起点不同可分组或使用严格有效样本掩码；填充样本不得进入损失、R² 或样本数。长时间轴分段累计残差/Jacobian时仍是同一条曲线的同一次拟合，不做分段 tau 平均。
6. 噪声预筛、峰值、R² 可批量化；保持 CPU 的短序列、常量、NaN/Inf 与阈值边界规则。选区的单条曲线也能调用该后端，Auto 可根据规模选 CPU。
7. 兼容/双精度优先；寿命单精度未通过验收前保持禁用，不能仅转输出 dtype 冒充单精度求解。

异常曲线允许按明确的“CPU 复核/回退”策略单独复核，结果记录 GPU 成功数、CPU 复核数和最终失败数；严格 GPU 模式不偷偷调用 CPU。若大多数曲线依靠 CPU 才完成，不可称该配置通过 GPU 验收。

单/双指数 GPU 都是本版要求。原型失败时提交真实阻碍和实验记录，继续解决或请用户调整科学约束；**不得自动把双指数降级为占位接口、默认 CPU，然后宣告本版完成。**

## 6. 最小卷积算法验证，为 1.1.2 准备

在内部算法注册表接入 `spatiotemporal_convolution`，提供固定单位核、均值核、非对称差分核的 CPU/CUDA 调用。此时不新增完整工具菜单或三维编辑器。

- 支持 HW 与 THW，输入核和中心/每轴偏移由参数提供；输出先采用 same。
- 定义卷积而非相关；与 SciPy/CuPy 对照，内部 halo、全局边界 reflect/constant、偶数/非对称核必须正确。
- 归一化不是自动操作；零和差分核不可除以权重和。复数和整数输出的 dtype 规则显式定义。
- 验证取消、CPU 回退、文件引用、metadata 和结果历史闭环；单凭一个函数测试通过不算接口验证完成。
- 1.1.2 复用切片器的 pyqtgraph OpenGL 视图基础，但本版不为预留而拆散其全部 UI。

## 7. 菜单与首选项整合

### 7.1 菜单决定

将现有首个空“主窗口”菜单替换为“选项”。它包含以下分类入口，均打开同一个设置窗口并定位相应页，不打开六种彼此独立的设置弹窗：

```text
选项
  常规与更新...
  外观与画布...
  绘图默认值...
  计算与加速...
  寿命拟合默认值...
  缓存与存储...
```

统一窗口采用左侧分类导航、右侧设置页、底部“恢复本页默认 / 应用 / 确定 / 取消”。菜单项和页名称一致；同一时刻只有一个窗口实例，重复打开仅聚焦并切页。优先非模态，不妨碍用户看任务和画布。

原“编辑”中的主题、计算设置、计算与加速、绘图设置、缓存设置迁移到“选项”，不保留双份可编辑实现。“坏点处理”是数据操作，继续保留原可用入口，本版不借此重新排列业务菜单。

“历史数据 → 历史与缓存管理”继续存在，负责查看、恢复、落盘、删除、名称标签、多选。其缓存设置区域改为摘要与“打开缓存与存储选项”链接，清理命令仍由历史管理执行。原方法名如 `compute_settings_dialog()` / `cache_settings_edit_dialog()` 可暂作定位统一页面的兼容入口。

### 7.2 分类迁移清单

| 页面 | 本版迁入内容 | 存储/当前入口 | 生效范围 |
| --- | --- | --- | --- |
| 常规与更新 | 启动时自动检查更新；版本与日志位置可显示为只读信息/跳转 | `should_check`、UpdateModule 中不再提示更新的入口 | 按既有检查间隔生效；`last_update_check` 是内部状态，不给用户编辑 |
| 外观与画布 | 深浅主题；画笔/填充/向量样式、anchor 形状/大小/方法等现有工具偏好，分为外观和工具默认值 | `appearance/theme`；`tool/pen_*`、`fill_color`、`vector_*`、`anchor_*` 等 | 主题应用后更新；工具默认值影响之后的工具操作，不能自动执行 anchor 或改已有 ROI |
| 绘图默认值 | 曲线颜色/线型/线宽/标记、网格、轴显示、热图色图/等高线 | 原 PltSettingsDialog 与 `plot/*` | 保存未来默认；显式“应用到当前结果图”才更新当前图，且不重跑算法 |
| 计算与加速 | 硬件状态、全局 CPU/GPU、精度、配额、回退；按算法覆盖和状态 | `compute/*` 与 ComputeSettingsDialog | 影响新提交任务，运行/已排队请求快照不变 |
| 寿命拟合默认值 | 从头/峰后拟合、峰位范围、R² 门限、tau 范围 | CalculationSetDialog 与 `cal_set/*` | 新任务使用；单位明确，不能把当前数据的单位永久写成全局单位 |
| 缓存与存储 | 缓存目录、浏览/打开目录、数组落盘阈值、交互数据 RAM 预算、启动清理临时缓存 | `tool/cache_*`、`tool/memory_budget_mb`；历史管理设置区域 | 新存储使用新目录；旧历史不移动、不删除，活动任务继续使用提交时目录 |

不能机械搬走的内容：

- 当前数据的单位、fps、轴映射、ROI、STFT 窗口/频段、CWT 小波/尺度等科学输入仍留在原工作区/算法弹窗。
- 当前画布伪彩开关、levels、最小最大值、当前帧、当前结果字段、当前绘图模式仍是局部状态；不因打开选项而重置，不在“工具默认值”页反向覆盖它们。
- 最近目录、表情使用记录、浮动窗口位置、布局序列化属于内部记忆状态，不做成偏好表单；布局操作继续在画布工具栏。
- 坏点修复、清除历史、清空全部缓存、检查更新和恢复数据是立即执行的命令，不伪装成“应用设置”里的副作用。

新工具默认值与老的共享 `tool_params` 有耦合，迁移时拆分“未来默认”和“当前画布状态”更新通道，避免全量广播整个字典导致伪彩消失。保留画布右键快捷编辑；其与默认值的原有联动需明确标注并通过同一控制器更新，不出现两份相互覆盖的真相。

### 7.3 设置页必须具备的交互

- 计算页复用/抽出 ComputeSettingsDialog 的 QWidget 内容，不把 QDialog 嵌进另一个 QDialog；其他旧设置窗同理，只抽相关表单，不进行无关重构。
- 大表格支持滚动、合理列宽、完整 tooltip。硬件检测异步、可超时，未安装 CUDA 也可进入其他页；关闭页面停止密集轮询，不终止用户计算。
- 后端与精度分开；每算法可覆盖精度，未设置的仍跟随全局。新增键建议 `compute/algorithms/<id>/precision`，不改变现有全局默认值。
- 算法能力至少区分“实现缺失 / 环境不可用 / 未验证 / 可运行 / 有性能依据”；不以自检成功替代数值与性能证明。
- GPU 状态显示实际运行设备、精度、回退原因；峰值显存和 RAM 预算要有单位。寿命单精度若未适配，禁用并给原因。
- 核心科学数值支持科学计数输入与合理验证，不延续固定 10000 帧上限限制未来长序列；不要在用户输入中途强制改成边界值。
- 使用现有主题、图标和点字号；在 1366×768、1920×1080 及 125%/150% 缩放下，底部按钮可见，字段不被挤成省略文本，不重演 dialog 字体异常缩小。

### 7.4 草稿、应用、迁移

设置控制器使用小型参数草稿，不持有或 deepcopy 数据数组。打开/切页/选色只改草稿，不立即写入当前字典或 QSettings。

1. 应用前验证所有脏页面：路径可写、范围有序、枚举有效、预算合法、设备偏好可解释；失败定位页面/字段，不先应用一半。
2. 通过后按依赖顺序更新已有 settings store 与主窗口参数镜像，再同步运行时组件。特别防止 MainWindow 的周期 save_params 把新设置覆盖回旧值。
3. 维护旧小配置快照并检查 QSettings 同步结果；运行时应用失败需恢复可恢复的配置并汇总报告，不虚假显示“全部已保存”。不声称 QSettings 与文件系统是天然原子事务。
4. “取消”丢弃上次应用以来的草稿；“确定”应用并关闭；“恢复本页默认”只改当前页草稿，不能清历史/缓存/性能档案。
5. 主题也在应用/确定后提交，避免取消后主题留在新状态；不以切主题重新导入数据或重新计算。
6. 保留 `appearance/*`、`compute/*`、`cal_set/*`、`plot/*`、`tool/cache_*` 等现有键。新增 UI 状态用 `preferences/*`；未知键保留，不重置旧用户配置。
7. 非模态窗口打开时，快捷工具栏可能更新同一字段：应用仅写用户改动字段，并检测同字段冲突；不能用旧快照整体覆盖其他入口的新修改。
8. 缓存目录切换调用现有经过验证的逻辑并增强任务租约保护；所有新写入采用新目录，旧数据引用保留。统一选项窗口不提供“切换时自动搬移/删除旧目录”。

历史管理页保留已确认的保留缓存/清理区分：启动清理和本次历史清除不删除用户明确落盘保留的历史，索引与文件及 UI 刷新同步。菜单整合不得绕过这些规则。

## 10. 验证矩阵与判定标准

### 10.1 科学与后端一致性

继续扩展现有 `test_compute_*`、`test_stft_pipeline.py`、`test_stage_d_pipelines.py`、`test_lifetime_pipeline.py`、`test_algorithm_registry.py`，按需新增 GPU 与 preferences 测试，不重复建测试框架。

| 项目 | 最小覆盖 |
| --- | --- |
| 注册与配置 | 未知算法、旧 ID、不同输出轴、实际后端不支持、严格 GPU、算法精度覆盖、参数冻结 |
| 分块 | 单块/多块相同；T/H/W 块长不整除；前后不等 halo；核大于块；源边界/内部接缝；32 位计数溢出 |
| CWT | 七种当前小波、单/多尺度、实/复数正弦、脉冲/常值、NaN/Inf、低频长核、短 T、四种浮点/复数 dtype；比较最终值及少量原始复系数以发现相位错误；质量分析二维谱不被信号归约替代 |
| 单指数 | 已知 A/tau/C，噪声、峰后不同起点、正负约定、基线、非均匀时间、NaN、常量、范围边界、负 R²、病态拟合 |
| 双指数 | 可辨识的两个分量、接近/退化分量、单分量极限、不可行初值、原非对称 bounds、分量标签、两寿命图与导出字段一致 |
| 卷积 | 单位核、均值、非对称差分；偶数核/偏移核；CPU/GPU 与整块参考；零和核不自动归一化 |

初始验收门槛应写入测试，以下为本版建议，不能为让 GPU 通过而单边放宽：

- CWT/固定核卷积：单精度 `rtol=5e-4, atol=5e-6*S`；双精度 `rtol=1e-8, atol=1e-10*S`，S 为参考输出的非零最大幅度。全零样例另测接近零的残差，不能以不合理的大 atol 掩盖污染。
- 良态、无噪声寿命样例：float64 寿命相对误差不超过 1e-4，R² 绝对差不超过 1e-6；与解析值及 CPU 分别比较，不只对比两种错误实现。
- 噪声真实样例比较参数、残差目标、有效掩码、失败率和筛选边界；双指数不可辨识样例不要求虚假的唯一 tau，而需一致的质量诊断与失败处理。
- 靠近筛选阈值的差异单独报告，按约定复核，不通过提高阈值或全局放宽误差让差异消失。新的复核在严格 GPU 模式应被禁止或明确要求用户允许。
- 默认有效路径的 shape、dtype、时间/空间单位和字段保持；GPU 结果不能混入显存数组引用或不可序列化对象。

若真实科学数据证明以上门槛需调整，先给出误差证据和业务影响，由用户确认后同时更新 CPU/GPU标准。已知旧科学缺陷的修复另列变更，不假称纯性能优化。

### 10.2 任务、缓存与设置

- 读、传输、核计算、拟合迭代、落盘、提交前分别取消；无孤立已注册半成品、无 GUI 阻塞、后续任务可继续。
- OOM、磁盘不足、目标 GPU 丢失、worker 崩溃、超时、自检失败只产生一条聚合错误；严格模式不能假成功，warning 不弹窗。
- 更换焦点、历史删除、切缓存目录和清理同时发生时，任务读取旧引用仍有效；按租约延迟回收，原文件不被写入。
- 无 CUDA、未安装 CuPy：首选项、CPU算法、历史和画布都正常，不因计算设置页初始化阻止打开应用。
- 旧 QSettings 完整迁移；打开即关闭、改色后取消、应用后再取消、单页恢复默认、设置冲突、磁盘写配置失败都测试。
- 历史缓存页的链接定位正确，手动清理与启动清理不删除保留项；新目录切换后旧项仍可恢复。
- 连续至少 10 次计算/取消/打开关闭设置，检查 RAM、VRAM、进程、映射、timer 和信号连接不持续增长。
- 大数据 smoke：恢复缓存 → CWT/寿命 → 历史 → 当前结果 → ROI/画布 → 导出；双指数逐字段验证原始数值和单位。

### 10.3 真实 GPU 验收与性能

扩展 `benchmarks/benchmark_compute_11.py`，记录后端、实际求解器、精度、设备/库版本、CPU复核数量、块参数、I/O/传输/内核/总耗时和峰值 RAM/VRAM。GPU 异步计时必须等待结果或使用 CUDA events，冷启动与热执行分开。[CuPy 性能指南](https://docs.cupy.dev/en/stable/user_guide/performance.html)

至少一台用户指定 CUDA 电脑完成 CWT 与单/双指数 GPU 真运行；本机模拟、mock、GPU 测试 skip、以及全部回退 CPU 都不能代替。延续此前约束，不擅自查询当前开发电脑型号以代表目标设备。

日常 float32 和默认双精度寿命分别测；当前极端 10000×400×400 按实际硬件条件选测，未来 TB 形状仅进行虚拟块预算测试，未经实际完整运行不宣称已验证 TB 吞吐。

默认 Auto 将“正确可运行”与“更快”分开。只有同精度/同输出、含 I/O 的可信性能证据才优先 GPU；未知档案保守 CPU，并可手动指定 GPU。目标卡上的双精度若慢于 CPU，保留 GPU 能力但诚实显示结果，不降精度凑加速倍数。
