# LifeCalor 1.0.15 规划：数据命名、表情标签与历史批量管理

- 编写日期：2026-09-12。
- 实现基线：`c7d0694`，`core/app_metadata.py` 当前为 `1.0.14`。
- 状态：待实现，供后续 Sol 直接执行；本文件不是完工记录。
- 目标版本：候选 `1.0.15`。本次只提交规划；实现、测试和用户验收后统一登记版本。
- 前序规划：`2026-09-10-lifecalor-startup-canvas-workspace.md`。用户已确认该轮更新完成，本轮不重复安排启动页和画布布局架构。
- 总目标：数据更容易辨认、查找和批量管理，同时让布局工具融入现有界面，不改变科学数据与计算语义。

## 1. 范围和明确不做的事

本轮必须完成：

1. 布局按钮及其菜单图标统一现有画布工具栏的颜色、线条和交互风格。
2. 在“历史与缓存管理”中修改所有数据的显示名称，保留原始名称可追溯。
3. 每项数据支持最多三个 Windows 原生表情标签，支持单项编辑和批量增删。
4. 数据树、历史查看、历史缓存管理统一显示新名称和标签，并支持名称与标签组合筛选。
5. 当前历史、可恢复历史均支持多选，配套批量落盘、恢复、删除和标签管理。
6. 改名、标签编辑、筛选、排序不能触发大数组读取、复制、统计或重算。

不纳入本轮：

- 为缩短文件而继续拆 MainWindow、全面目录搬迁或全仓库冗余清理。
- 重写画布布局算法、渲染线程、计算器、STFT/CWT、导入算法和数据存储格式。
- 引入数据库、WebEngine 界面、自制表情商城、全局标签本体或多用户同步服务。
- 建设通用并行任务调度器。本轮批量缓存操作复用任务管理，并顺序执行。
- 按标签自动分组计算、自动给新结果继承“已验证”等标签，或批量重命名规则引擎。
- 修改用户实验数据、原始文件名、缓存 NPY 文件名和不相关打包文件。

以下为本次定向阅读确认，不代表已运行全部回归测试：

| 位置 | 当前情况 | 本轮应做 |

| `core/history/manifest.py` | 索引含原始 name、数组引用；id 由 kind、serial_number、timestamp 组成；直接覆盖写 JSON | 附加展示元数据、原子保存、受控更新和旧索引兼容 |

| `core/DataManager.py` | 原始数据和结果都有历史快照；数组字段访问可能解析缓存；历史 deque 有容量限制 | 新展示字段只复制轻量元数据；批量恢复需预检历史容量 |

所有入口复用一套名称、标签、身份和筛选规则，不允许每个窗口独立拼字符串。

## 3. 数据契约：改显示名称，不改科学数据身份

### 3.1 哪些对象可以编辑

- `Data` 和 `ProcessedData` 的所有数据形态均可编辑：标量、向量、曲线、二维图像、视频、非视频三维矩阵及高维数据。
- 内存历史、已经落盘的历史、尚未恢复的索引项均可编辑。未恢复项直接修改其索引，不先恢复数组。
- 根对象的主数据字段 `data_origin/data_processed` 使用根对象的名称和标签，不创建重复的“主数据别名”。
- `out_processed` 内作为独立数据展示或选择的子结果也支持展示别名和标签；原始 key 保持不变。在单项编辑窗口中通过“编辑对象”树选择根数据或子结果。
- `fps`、单位、轴定义等配置参数不是可重命名的数据；不得借改名改科学参数 key 或数值。
- `ImagingData` 是显示派生对象，跟随所属数据的展示信息，不引入另一份独立命名。临时画布若无有效历史来源，只展示已有来源名，不伪造历史。

### 3.2 唯一身份

- 根数据沿用现有身份 `(kind, serial_number, timestamp)`，已落盘项复用现有 manifest id，不生成全库 UUID。
- 缓存索引定位还必须携带它所属的缓存目录，不能只用“当前设置中的目录”。
- 子结果身份由根身份和结构化字段路径组成，例如 `["out_processed", "spectrum"]`。不要用用户可改名字定位对象，也不要用点号拆分实际字典 key。
- 排序、筛选、改名、恢复均通过存入 `Qt.UserRole` 的身份取对象，不通过行号、显示文本或时间格式化字符串反推。
- `_append_unique_history/_remove_unique_history` 只匹配同一真实身份；当前“timestamp 相同或 serial 相同”的规则需作本轮必要修正。来自不同启动会话、序号相同的数据不能互相覆盖。
- 不借此全局重写已有时间戳接口；在本轮入口中增加完整身份解析并保留必要兼容适配。

### 3.3 展示字段

建议在数据对象及 manifest item 中使用独立 `annotations` 字段，而不是塞入算法 `parameters/out_processed`：

```json
{
  "version": 1,
  "display_name": "样品 A 的背景扣除结果",
  "tags": [],
  "fields": [
    {
      "path": ["out_processed", "spectrum"],
      "display_name": "频谱",
      "tags": []
    }
  ]
}
```

约定：

- 根 `display_name` 为空时回退原始 `name`；子结果为空时回退实际 key。原始名称、key、来源文件始终可在详情或 Tooltip 查到。
- 用户“重命名”修改展示字段；允许同名数据，靠类型、来源、时间和身份区分，不擅自追加数字。
- 名称去除首尾空白，拒绝换行、控制字符；默认上限 128 个 Unicode 码点，超限拒绝提交，不静默截断。
- 提供“恢复原名”。空输入按恢复原名处理，在编辑窗口中明确显示回退后的名称。
- 标签是保序、去重后的 Unicode 字符串列表，数量 0 到 3。它们不拼进 `name`，更不拼进公式、文件路径和 manifest id。
- 子结果未设置 tags 时跟随根标签；显式 `[]` 表示该子结果无标签。子结果可选“跟随所属数据”；不把父子标签简单合并突破三个上限。
- 新运算创建的新数据默认无别名、无标签；沿用原有结果命名和来源关系。用户对源数据的判断标签不能自动变成新结果的判断。
- 改名/加标签不是新的科学处理步骤：不修改时间轴、dtype、单位、科学数据时间戳，不新增处理历史，不增加数组版本。

### 3.4 保存与同步

- 当前内存数据仅修改轻量元数据；不为保存名称或标签触发强制落盘。关闭程序后未持久化的数据仍按现有历史策略处理。
- 强制落盘时将 annotations 与现有数组引用一并写入索引；旧索引没有此字段时自动使用原名与空标签。
- 恢复时还原 annotations，并记录其来源索引目录与 id。用户清空本次历史后，已落盘名称和标签必须保留。
- 同一来源索引恢复出的当前实例、历史快照、画布来源摘要是同一展示身份，编辑后应同步；尚未打开的视图下次查询得到最新结果。
- 另一个目录里的独立索引副本不做全盘搜索和自动同步。切换缓存目录后，对已恢复数据的编辑仍定位其原索引，不能误改新目录同名项。
- 已关联索引却无法保存时，报一次错误并保持编辑前状态，不假装保存成功；内存独有数据编辑不依赖磁盘。一次编辑涉及多个目录时逐目录报告，不声称跨目录原子事务。
- 元数据写入使用同目录临时 JSON 文件、关闭文件后原子替换；失败保留旧索引。读-改-写必须在同一受控事务中完成，单独原子替换不能防止丢更新。
- 编辑、落盘完成回调、清理失效索引、删除和刷新涉及的写入统一串行或加同目录共享锁，并在提交时重新读取最新索引。后台落盘不能把用户刚改的名称覆盖回去，也不能把已删除的索引“复活”。
- 任务开始时固定缓存目录和目标身份。本轮相关批处理运行时禁用目录切换及冲突的缓存维护动作，完成后恢复。
- JSON 保持 UTF-8 和 `ensure_ascii=False`；保留未知字段。本轮只加可选字段，不破坏旧数组引用格式，不自动把未知高版本索引降级覆盖。
- 名称更新不修改条目的原始保存时间；如需审计修改时间，使用单独 annotations 更新时间。
- 同一进程对同目录的写入必须受控；不同 App 进程同时写同一缓存目录不在本轮并发承诺内，不得宣称跨进程事务安全。

实现宜增加纯元数据模块 `core/history/annotations.py`，提供展示名读取、标签校验、轻量复制、身份与匹配辅助函数；不导入 GUI 或 DataManager，避免循环依赖。控制器负责持久化和变更通知，不再建立第二套“影子历史”。

## 4. 交互设计

### 4.1 历史与缓存管理

保留“当前历史 / 可恢复历史 / 缓存设置”三个页签。前两个页签统一为：

- 顶部：名称搜索框、数据类型下拉、标签筛选菜单、清除筛选工具按钮。
- 中部：可排序、多选的列表；“名称”和“标签”相邻，原有形状、dtype、体积、时间、状态等信息继续保留。
- 底部：固定位置的“已选 N 项 / 显示 M 项 / 共 K 项”和紧凑操作栏。
- 单项选中时可“编辑名称与标签”；F2 打开重命名编辑，右键菜单也提供同入口。多项选中时禁用单项重命名，提供批量标签操作。
- 缓存目录、阈值、手动清理入口不搬家；标签筛选不放在缓存设置页。
- 名称列可伸缩；类型、dtype、标签列有合理宽度；支持横向滚动与完整 Tooltip，不对所有列平均 Stretch。
- 工具型按钮用现有图标体系，悬浮提示说明作用；危险删除动作不和刷新/编辑混淆。
- 双击单项沿用当前设置/恢复行为；不能因 Ctrl 单击或范围多选自动恢复数据。

标签编辑窗口：

- 根数据和可命名子结果用左侧紧凑树选择；右侧为原始名称只读、显示名称输入和三个固定尺寸标签输入位。
- 标签输入位支持粘贴、删除；输入框获得焦点后使用 Windows 原生 `Win + .` 表情面板。快捷键写在 Tooltip 与使用指南里，不新增自制表情挑选器。
- 编辑中保留本地草稿，点击应用才提交。输入法尚未完成组合时不立即报错。
- 多选编辑标签通过同一个对话框选择“添加标签 / 移除标签 / 清空标签”，不提供含糊的覆盖全部；清空需明确确认。
- 批量添加先预检每项最终标签数。任何一项超出三个，整批不修改，并列出超限条目供调整；不静默截断，不连续弹 N 个窗口。

### 4.2 Windows 表情的技术边界

- 原生输入是系统能力，微软提供的快捷键为 `Win + .` 或 `Win + ;`。不模拟全局按键、不安装键盘钩子，不把打开系统面板作为 App 启动条件。[微软快捷键说明](https://support.microsoft.com/en-us/windows/keyboard-shortcuts-in-windows-dcc61a57-8ff0-cffe-9796-cb9706c75eec)
- 一个表情可能含多个码点。肤色修饰、国旗、键帽和 ZWJ 组合必须作为完整标签保存；不得用 `len(text) <= 3` 或 `QLineEdit.setMaxLength(3)` 实现标签上限。[Unicode 文本分段标准](https://unicode.org/reports/tr29/)
- 本轮建议使用轻量 `emoji` 库进行完整表情识别，每个输入位提交时必须是一个完整、受支持的表情，不接受夹杂普通文字的标签。该库提供单表情校验和序列识别，不要自写 Unicode 范围正则。[项目 API 文档](https://emoji-python.readthedocs.io/en/latest/api.html)
- 本次只读检查发现项目虚拟环境没有 `emoji/regex`。实现阶段明确新增并锁定所用 `emoji` 版本，记录安装与打包依赖；不顺带升级 Qt、NumPy，不在运行时联网下载字符数据。本次规划不安装依赖。
- 保存时采用一致的 Unicode 规范化，保留 ZWJ、肤色及合法变体选择符。去重按规范化后的完整序列，不能逐字符拆分或任意移除选择符。
- 标签区域使用支持表情的字体回退，例如 Windows 的 Segoe UI Emoji；名称、表格、对话框字体继续沿用现有 DPI 方案，不全局换字体。
- 实机检查系统面板焦点、中文输入、组合表情及屏幕缩放。Qt/系统可能以单色显示部分字符，不能通过截图冒充系统原生彩色支持。
- 系统面板不可用时仍可粘贴合法表情；未支持的序列在输入处提示，拒绝提交，不拆成多个标签或丢失已存数据。

### 4.3 筛选规则

统一匹配纯元数据：

- 文字搜索：显示名称、原始名称、子结果实际 key 和来源名；不搜索数组内容，不调用 `resolve()`、`np.asarray()`、min/max 或数据详情全文序列化。
- 类型筛选复用已有数据分类，而不是把 `Data/ProcessedData` 与“图片/视频”混为一类。
- 标签菜单来自当前视图全部条目的有效标签，不因当前筛选把可用选项消失掉；支持“任意标签”和“无标签”。
- 多个已选标签默认匹配“包含任意一个”，不同条件组合为“文字 AND 类型 AND 标签条件”。“无标签”与具体标签选择互斥。
- 大小写不敏感；中文和表情按规范化文本处理，不按本地编码字节匹配。
- 共享树中命中子节点时保留祖先作为上下文。根数据自身命中时允许查看其完整参数子树；上下文节点不因此变为可操作数据。
- 当前历史、可恢复历史各自保留筛选与排序状态。清除筛选不修改数据，也不清空标签。
- 每次刷新按稳定身份保留仍可见的选中项、滚动位置和展开状态；被筛掉的行必须取消选择。
- `Ctrl + A` 仅选择当前页签、当前筛选后可见的可操作条目。显示数量不包含仅用于上下文的树分组。

### 4.4 所有名称显示入口

必须接入同一展示访问器，不进行全局搜索替换 `.name`：

| 界面 | 本轮行为 |
| --- | --- |
| 当前历史、可恢复历史 | 名称与标签列；原名和来源在 Tooltip/详情；支持组合筛选 |
| 原始/处理历史选择窗口 | 同样显示新名称与标签；取数使用稳定身份；当前焦点为空也能查看类级历史 |
| 全部历史数据树、计算器数据选择树 | 名称、标签、原始 key 区分；保持现有“设为当前/加入运算/显示”等操作 |
| 画布标题和画布数据详情 | 更新所属数据展示名与标签；长标题缩略但 Tooltip 完整；不重建画布 |
| 计算器已经绑定的数据 | 更新其来源展示文本；A/B/C 公式变量与数据绑定不变，不自动发起预览或计算 |

已有结果曲线的自定义名称、公式、已完成任务日志不追溯改写。本轮不改变导出文件自动命名规则；导出选择界面显示新名，但既有路径和文件保持原样。若用户后续要求输出文件也随别名命名，另作明确文件名净化规则。

## 5. 多选必须配套完整批处理

### 5.1 支持矩阵

| 操作 | 当前历史 | 可恢复历史 | 多选约定 |
| --- | --- | --- | --- |
| 编辑名称 | 支持 | 支持 | 仅单选；子结果通过编辑对象树选择 |
| 添加/移除/清空标签 | 支持 | 支持 | 支持；根项批量编辑，不隐式覆盖子结果自己的标签 |
| 设为当前/显示 | 支持 | 单项恢复后沿用现有行为 | 仅单项；不自动弹出多个画布 |
| 强制缓存落盘 | 支持 | 已有持久缓存无需重复落盘 | 当前历史顺序处理选中项 |
| 恢复 | 无需重复恢复 | 支持 | 全部成功项进入本次历史，见下述容量与激活约定 |
| 删除 | 删除所选本次历史 | 删除所选索引，可选删除独占文件 | 一次确认、一次汇总；删除边界不同，文案必须明确 |

列表采用 `ExtendedSelection`、整行选择、Ctrl/Shift 范围操作；不能只改 selectionMode 而保留单项业务。

### 5.2 顺序任务和响应性

- 操作开始时快照稳定 ID、所属目录和可见选择范围，不持有后续会被清树销毁的 item 对象。
- 批量落盘/恢复复用 `TaskCoordinator` 的一个批任务，逐项执行；当前线程完成并释放后再调度下一项。
- 不以 for 循环启动多个 `force_cache_history_item/restore_manifest_item`；它们目前会覆盖单 worker/thread 字段，并各自弹窗。
- 缓存实际读写和大型索引 I/O 在工作线程；元数据界面更新在主线程。索引更新使用纯字典快照，线程不访问 QWidget。
- 任务显示“第 i/N 项 + 当前数据名 + 当前项进度”；能取到字节总量时按字节加权，未知时显示阶段/计数，不伪造百分比，不反复将总进度归零。
- Esc 与任务面板取消复用已有 token。取消停止当前支持中断的工作并阻止后续项启动；已完成项保留、部分 NPY 按现有安全规则清理。
- 不使用主线程长时间 wait、进程强杀、`QThread.terminate`、忙等或重入 `processEvents`。
- 同时只允许一项会变更该缓存目录的批处理；批次运行时禁用冲突动作，但界面筛选、拖动和查看已加载数据仍可使用。
- 关闭管理窗口后任务由控制器持有；已销毁窗口不再接收更新。不能随 dialog 销毁正在运行的 QThread。
- 单项失败记录上下文并继续不依赖该项的后续操作；用户取消则停止整批。完成后一次汇总成功、跳过、失败和未执行项。
- warning 记日志及状态，不弹错误窗；error 通过已有 diagnostics 以整批完整事件至多弹一次。不得把每项 traceback 拆行弹出。

### 5.3 恢复、重复项和历史容量

- 恢复列表中的多项首先建立轻量对象和数组引用，并逐项注册到对应类级历史；不要预先物化所有选中大数组。
- 已在当前历史的同一身份跳过重复恢复，保持其当前绑定与最新展示信息；同名或同序号的不同身份不能跳过。
- 现有 `Data.history/ProcessedData.history` 是有界 deque。预检本批新增数量和剩余容量，数量超限时整批不启动，并提示需要减少选择或移除部分本次历史；不静默淘汰刚恢复的项，也不改为无限历史。
- 单项恢复保持原来的“加入历史并设为当前”。多项恢复全部进入历史，不逐项抢占焦点、物化数组或弹添加画布窗口。
- 多项恢复结束保留用户原当前数据；用户可从任一成功项点击“设为当前/显示”。若开始时没有当前数据，则仅在结束时激活首个成功根项一次。
- 激活所需的缓存读取仍走已有异步读取流程。数据进入历史不以读取数组完成为前提，不恢复到“只有设为当前后才出现在历史里”的旧问题。

### 5.4 删除与缓存保护

- 删除当前历史：仅从本次历史移除所选项，不删持久索引和它保护的 NPY；其他未选条目不受影响。
- 删除可恢复历史：一次对话框展示选中数量，默认仅删除索引；用户可明确勾选“同时删除不再被引用的缓存文件”。
- 物理删除前计算删除集合之外的引用，同时保护剩余索引、本次历史、当前对象、画布和运行中任务。
- 两个被删索引彼此共享的文件在没有任何剩余引用时才可删；仍被未删数据使用的文件必须保留，并在汇总中说明。
- 不按名称猜路径，不删除索引声明范围之外的路径，不递归清空用户目录；继续使用现有缓存路径验证规则。
- 删除正在落盘/读取的同一项时拒绝冲突操作或等其安全完成，不能先删文件再等待 worker 报错。
- 文件已缺失的索引仍可以删除；只删索引后保留的无引用文件可由现有孤立缓存清理回收。
- 删除或取消后立即刷新索引列表、筛选结果与选择计数；被删项不能继续留在旧选择集里。
- 磁盘文件删除不能真正回滚。发生部分失败时按实际结果刷新并汇总，不能报告“全部成功”或声称已恢复被删文件。

## 6. 布局图标与工具栏风格

- 替换当前 `QStyle.SP_TitleBarNormalButton`；使用清楚的四分画布图形表达布局，不使用应用窗口“还原”图标充当排列。

## 8. 可执行验收清单

自动化测试以微型数组、临时缓存目录、受控假 worker 为主，不能依赖用户实验目录。

| 类别 | 必须证明 |
| --- | --- |
| 向后兼容 | 旧 manifest、没有 annotations 的对象恢复后原名和数据照常可用；未知字段不丢失 |
| 身份 | 同名、跨会话同 serial、排序/过滤后的选中项不串线；实际 payload key 和公式变量不变 |
| 纯元数据 | 用“任何数组读取都会抛错”的 ArrayRef/对象替身，完成编辑、筛选、排序和刷新；NPY 路径、文件修改时间不变 |
| 快照 | 当前实例、历史快照和同来源索引同步；改名不新增科学历史；独立子结果标签不意外共享可变列表 |
| 恢复与目录 | 改名落盘、清本次历史、重启恢复，名称标签仍在；切换目录后编辑旧恢复对象不误写新目录 |
| 索引事务 | 模拟权限不足、替换失败、后台落盘完成与编辑交错；旧索引可读，不丢最新标签、不复活已删项 |
| 标签 | 0/1/3/4 个、重复、普通文字、空输入、肤色、国旗、键帽、ZWJ、变体选择符、中文输入法提交 |
| 筛选 | 原名/新名/标签、无标签、类型联合；子节点命中保留上下文；清除筛选不会修改数据 |
| 选择 | Ctrl/Shift、可见 Ctrl+A、排序后删除、过滤掉原选中项、刷新后恢复选择；旧历史选择框取到正确对象 |
| 容量 | 批量恢复超出 deque 容量时不启动、不静默丢历史；足够容量时所有成功项立即在历史中可见 |
| 批任务 | worker 不重叠，任务进度可追踪；中途取消保留已完成项，不执行后续项，无 GUI wait |
| 部分失败 | 第二项失败、其他项成功；至多一个汇总错误窗，每项完整上下文进日志 |
| 删除安全 | 仅删本次历史不删持久缓存；批删索引保护剩余索引、当前数据、画布与工作线程持有文件 |
| 活动视图 | 改名时播放、ROI、伪彩、帧号、缩放、画布 ID、计算器绑定和四象限布局均不变 |
| 窗口关闭 | 批任务期间关闭/重开管理窗口，不出现已删除 Qt 对象回调和仍运行线程析构 |
| 图标 | 资源存在且非空；图标替换不改动作连接；100%/125%/150%/200% 缩放下清晰且文字不截断 |

优先扩展现有 `tests/test_history_cache_manager.py`、`tests/test_data_cache_integration.py`、`tests/test_canvas_data_details.py`、`tests/test_canvas_workspace.py`；按职责补 annotations、筛选、多选与批处理测试。使用项目已有 unittest/pytest 风格和虚拟环境，不迁移测试框架。

用户真实数据验收顺序：

1. 同时准备普通导入、处理后结果、含 out_processed 的数据和未恢复的旧缓存。
2. 改名、添加三个表情，从不同历史入口和计算器选择树核对；按旧名、新名、标签筛选。
3. 保持大视频播放时编辑名称、刷新和筛选，确认没有整段数组读取、长卡顿或帧状态丢失。
4. Ctrl/Shift 多选、筛选后全选、批量落盘；中间取消一次，再重试。
5. 清空本次历史并重新打开程序，批量恢复，核对名称标签、当前焦点和历史容量行为。
6. 删除部分共享数据的索引，确认未删项与正在显示数据仍能访问；再测试只删本次历史。
7. 检查布局按钮、右键菜单、浮动画布和不同缩放比例；这些操作不改变伪彩、ROI 或持久布局。

## 9. 给 Sol 的执行说明

以当前仓库为准阅读上述落点，按 A → B → C → D 完成一个版本。先实现并验证轻量展示元数据契约，再扩散到各界面，不对数据对象做盲目的全局 name 替换。不重新执行前序已完成的启动/布局重构，不追加 MainWindow 瘦身指标。

本轮验收核心不是“增加了几个按钮”，而是：同一数据在各处名字一致、标签可持久恢复、筛选不读大数组、多选不选错对象、批处理不阻塞界面、删除不破坏仍被使用的缓存。

完成报告应列出实际改动、目标测试结果、尚待用户实机验证项与提交号。只有实际完成的内容才能写入更新日志；不要把此规划的待办条目直接写成发布成绩。
