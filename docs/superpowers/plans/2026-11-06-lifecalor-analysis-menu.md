# LifeCalor 计算算法分类与菜单集成规划

- 核查日期为 2026-11-06，算法盘点与首期实施基线为 `1.1.1 / a3bf420`；与 `1.1.2 / 1798dde` 集成时保留主线已交付的独立时空卷积工作台，入口归属见下文。
- 当前工作区是 detached HEAD，并带有前次依赖配置与交接文档改动。本规划记录静态源码核查结果，首期菜单与共享入口已实施，结果见文末实施记录。
- 目标是在菜单栏提供按用途划分的高级操作与分析入口，让菜单、左面板和图上快捷入口复用参数、输入校验和执行逻辑。

## 1. 分类口径

按用户要处理的对象和分析任务划分为八类。模型、窗函数、小波和统计方法作为算法参数，CPU/CUDA 作为执行后端。列表中的“已有入口”表示源码已经连接到相应界面，实际接入条件和发现的问题另列。

菜单归属按操作目的划分。“高级操作”集中数据修复、通用数组运算、切片整理和独立时空卷积工作台。“分析与处理”集中科学分析及其预处理、统计、变换、拟合和运动分析。时空卷积沿用 1.1.2 的单一入口。下表同时盘点两个菜单涉及的计算能力。

本目录涵盖背景归一、坏帧检测与修复、统计、时频变换、拟合、物理参数换算、光流及表达式运算。伪彩、亮度映射、画布布局、裁剪、缩放、导入导出和历史管理归入相应工作区。寿命前后卷积属于有数值意义的处理，随算法参数列出。SIF 导入里的显示归一化、图像装饰和通用切片操作作为配套功能。

## 2. 当前计算能力清单

### 2.1 预处理与修复

| 计算项目 | 输入及实际运算 | 现有入口与实现状态 |
| --- | --- | --- |
| EM 背景归一化 | THW 序列，前 N 帧的逐像素中位数为背景 B，计算 `(I-B)/B` 并保护近零背景 | 左面板 EM → 数据预处理，`MassDataProcessor.pre_process()` → `run_preprocess_pipeline()`，已有 CPU 分块路径 |
| 异常帧自动检测 | THW，逐帧均值差分的 MAD 离群检测，输出坏帧编号 | 高级操作 → 坏点处理，`DataProcessor.detect_bad_frames_auto()`。算法函数已有，自动检测的异步返回链路需修复 |
| 坏帧邻帧修复 | 按坏帧列表，用前后 N 帧中的有效帧均值替换异常帧 | 同一坏帧窗口，`DataProcessor.fix_bad_frames()`。当前面向原始 Data 并原位更新，接入时要明确目标与完成状态 |
| 寿命前后空间卷积与独立时空卷积 | 寿命前后处理的 smooth、gaussian、sharpen、edge、laplacian、average 六类核；独立 HW/THW 核支持预设及逐层自定义权重 | 寿命热图参数页，`LifetimeCalculator.apply_custom_kernel()` 及寿命管线。1.1.2 已交付独立 CPU 卷积工作台，从“高级操作 → 时空卷积”进入，支持预览、后台执行、历史恢复与导出 |

### 2.2 统计与信号提取

| 计算项目 | 输入及主要结果 | 现有入口与实现状态 |
| --- | --- | --- |
| ROI 时序统计 | THW + HW mask，逐帧计算均值、最大、最小、中位数、0.75 分位数、标准差、求和、方差八种统计 | Anchor 快速提取，`DataProcessor.get_fast_selection()`。输出曲线，菜单需增加显式区域和统计方法选择 |
| 全场及选区平均时序 | THW → T，输出 `signal_average` | “其他方法 → 时序信号快速提取”及 EM 的“选区信号均值变化”，经 `CalculationThread.easy_process()`。现有 ROI 路径的分母与 Anchor 均值不同，见第 5 节 |
| 当前帧 ROI 值分布 | HW 或 THW 的指定帧 + mask，直方图及有效像素、均值、标准差等统计 | “其他方法 → 选区分布统计”及 Anchor 值分布，`DataProcessor.value_distribution_from_frame()` |
| 时间平均振幅图 | 沿 T 轴执行 `mean(axis=0)`，THW → HW | EM 单通道页和“其他方法”中的“累计时间振幅图”，`MassDataProcessor.accumulate_amplitude()`。集成后推荐名称为“时间平均振幅图” |

### 2.3 时频与频域分析

| 计算项目 | 输入及主要结果 | 现有入口与实现状态 |
| --- | --- | --- |
| STFT 时频计算 | THW → T′HW，选定频带的平均幅值，包含变换时间轴 | EM → 执行短时傅里叶变换，`process_EM_stft()` / `MassDataProcessor.python_stft()`，CPU/CUDA 管线已有，六类窗为参数 |
| STFT 质量分析 | 先求全场平均时序，再计算频率 × 时间系数谱 | EM → STFT 质量评价，`quality_EM_stft()` / `quality_stft()`，现有 CPU 路径 |
| CWT 时频计算 | THW → THW，对所选尺度的 `2*abs(coef)/sqrt(scale)` 取均值 | EM → 执行连续小波变换，`process_EM_cwt()` / `python_cwt()`，七种小波及 CPU/CUDA 管线已有 |
| CWT 质量分析 | 全场平均时序 → 尺度 × 时间谱 | EM → CWT 质量检验，`quality_EM_cwt()` / `quality_cwt()`，Auto 使用 CPU，可显式选择已有 CUDA 路径 |
| 逐帧二维 FFT | 空间二维变换，输出完整复频谱、幅度、相位和 log 幅度图 | EM 全细胞页及“其他方法”，`process_tDFT()` → `twoD_fourier_transform()`。当前界面路径使用 NumPy |
| 逐帧二维逆 FFT | 从完整复频谱重建实值图像序列，优先读取 `out_processed['twoD_FFT']` | “其他方法”，`process_tDiFT()` → `twoD_inverse_fourier_transform()`。单帧形状路径需核对 |

STFT/CWT 的质量图把系数平方后转为 dB 展示。曲线 Welch PSD 有自己的采样率与归一化定义，菜单使用各自准确名称。[质量图展示](../../../core/ResultDisplayWidget.py)

### 2.4 寿命与物理参数

| 计算项目 | 输入及主要结果 | 现有入口与实现状态 |
| --- | --- | --- |
| 区域指数寿命拟合 | 区域平均衰减时序，单/双指数拟合，输出寿命、拟合曲线及 R² | 超快成像 → 指数衰减寿命曲线，`region_analyze_start()` → `CalculationThread.region_analyze()`，CPU 路径 |
| 像素级寿命热图 | 逐像素单/双指数拟合。双指数保存两个 tau、两个 amplitude、baseline、R² 与 fit_status | 超快成像 → 选区寿命热图，`distribution_analyze_start()` → 寿命管线，CPU/CUDA 路径已有，旧模型文案和控件绑定需修复 |
| 扩散系数分析 | 线 ROI 的多帧空间剖面，逐帧一维高斯拟合求方差，再拟合方差—时间斜率，`D=slope/2` | 超快成像 → 载流子扩散系数计算，包含线 ROI、选帧、高斯拟合、方差拟合四步。最后的线性拟合目前位于结果展示方法 |
| 传热系数热图 | 先计算或读取寿命，按 `tau >= 0.1` 时 `42.72/tau`、其余为 0 换算，可加后卷积 | 寿命热图参数页已有“传热系数热图”按钮，`heat_transfer_start()` / `heat_transfer_calculation()`。固定系数、单位与适用领域应在参数页说明 |

### 2.5 单通道电生理分析

| 计算项目 | 输入及主要结果 | 现有入口与实现状态 |
| --- | --- | --- |
| 二维高斯拟合信号提取 | 已确认 ROI 的序列，逐帧二维高斯拟合，提取振幅时序并做阈值处理 | EM → 单通道 → 选区二维高斯拟合，`process_tDgf()` / `twoD_gaussian_fit()`。当前结果重点是单通道振幅，完整中心、宽度等参数图尚需另行接入 |
| 简单单通道提取 | 已确认 ROI 的序列，逐帧取最大值，未过阈值时可回退到均值 | EM → 单通道 → 简单单通道提取，`process_simple_scs()` / `simple_single_channel()` |

两项均使用 `SCSComputePop`，默认选择策略要求 `Roi_applied`。开闭事件持续时间、上升/下降时间指数拟合目前只有未启用的辅助函数，列入后续能力候选。

对应辅助函数为 `calculate_amp_dur()`、`fit_exponential_time()`。旧 `lifetime_map_cal()` 是寿命图的兼容入口。CWT 页面中的 Julia 项目前未参与实际执行分派，现有时频执行以 Python 和已接入的 CUDA 路径为依据。

## 3. 菜单结构建议

“高级操作”包含坏点处理、数据计算器、数据切片器和 1.1.2 已交付的时空卷积。新增顶层“分析与处理”，放在“控制台”和“高级操作”之间，提供科学分析入口。运动分析只有一个主要入口，直接列在该菜单末段，减少层级。两个菜单的职责与结构如下。

```text
分析与处理
  分析预处理
    EM 背景归一化…
  统计与信号提取
    ROI 时序统计…
    全场平均时序…
    当前帧 ROI 值分布…
    时间平均振幅图…
  时频与频域分析
    STFT 质量分析…
    STFT 时频计算…
    CWT 质量分析…
    CWT 时频计算…
    二维傅里叶变换…
    二维傅里叶逆变换…
  寿命与物理参数
    区域指数寿命拟合…
    像素级寿命热图…
    扩散系数分析…
    传热系数热图…
  单通道电生理
    二维高斯拟合信号提取…
    简单单通道提取…
  曲线分析
    Welch 功率谱密度                  [互斥模式]
    曲线幅值频数分布                  [互斥模式]
    恢复原始曲线                      [辅助动作]
    区间主峰分析                      [开关]
  ────────────────
  心肌细胞运动分析…

高级操作
  坏点处理…                          [检测与修复坏帧]
  数据计算器…
  数据切片器…
  时空卷积…                          [独立 HW/THW 卷积工作台]
```

单/双指数在各寿命入口内选模型。STFT 窗、小波种类和 CPU/GPU 选择在对应参数页设置。集成 1.1.2 时，独立时空卷积保留“高级操作”中的原有入口；“分析与处理”不再重复增加卷积动作。坏帧检测与修复、数据计算器、数据切片器和时空卷积统一归属“高级操作”。左面板的“基础运算器”复用高级操作中的同一计算器动作。

## 4. 点击之后的交互

### 4.1 参数准备与执行

- 带省略号的入口先进入参数准备。已有 STFT/CWT、单通道、ROI 分布和心肌运动窗口直接复用，高级操作中的计算器复用现有工作区。
- 寿命热图、区域拟合、传热、EM 预处理、扩散等依赖左参数页的项目，首期菜单定位到同一分析页，并突出目标参数块与执行按钮。扩散页展示完整四步工作流。
- 分析页的导航独立于导入格式下拉框，共用时空控件的启用规则由当前算法决定。菜单选择算法后，所选输入、时间轴和空间单位由输入上下文及参数页明确表示。
- 左面板按钮与菜单共用准备、校验与提交方法。用户确认参数和输入后登记后台任务，取消准备窗口时结束本次准备。
- 曲线工具共享 `graph_plot.action_time/action_psd/action_hist/action_peak` 和互斥组。进入 PSD/Histogram 时取消峰工具的勾选并隐藏选区，开启峰工具时选中原始曲线模式并恢复原数据。两处菜单的选中态与实际显示同步。

### 4.2 输入对象与可用性

| 输入对象 | 准备页需展示或校验 |
| --- | --- |
| 图像与视频数组 | 名称、原始/处理数据身份、shape、dtype、轴、时间轴、FPS、空间尺度。时间算法需要有效 T 轴，时间平均图要求序列输入 |
| ROI 算法 | 数据来源与 ROI 所属来源匹配、mask 形状、非空像素、ROI 类型。扩散使用线剖面，普通统计使用区域 mask |
| STFT/CWT | 默认模式沿用预处理数据的查找规则，同时向用户展示最终匹配的历史项。窗口长度、频率、采样率等先校验 |
| 逆 FFT | 完整复频谱来源及轴，明确选择 `twoD_FFT` 字段 |
| 物理量拟合与换算 | 时间和空间单位、拟合范围、模型、失败/筛选状态，传热固定系数及寿命字段。双指数当前主结果为 tau1，准备页显示实际换算来源 |
| 曲线分析 | 当前曲线绘图区、作用曲线数量、名称和来源语义。现有整图模式覆盖全部缓存项，接入时逐项验证算法条件，峰工具取第一条可见曲线 |
| 数组计算器 | 多数据来源、表达式、预期 shape/dtype、预计内存及 metadata 继承来源，复用现有计算器验证 |

现有 `SelectionController` 的默认模式可能从处理历史中回溯指定 `type_processed`。菜单准备页要显示解析后的真实输入。一次确认后的 Data/ProcessedData 引用、ROI 和参数快照直接交给提交方法，避免第二次隐式选择。

菜单展示与可用性计算只读取对象、metadata 和 ROI 状态。准备页可在没有当前画布时引导选择历史数据，计算器支持空工作区启动。执行按钮依据真实输入条件控制。曲线绘图区没有可用曲线时，对应曲线动作禁用并提供原因。

Welch PSD 的来源需要是合法时序。预计算 ROI 直方图是 bin/count 数据。首期采用整图切换时，先校验全部待转换项，混有此类数据时提示用户单独绘制合格时序后再分析。曲线分布模式复用预计算直方图的现有显示分支，峰工具按实际选定的 XY 数据做区间定量。

### 4.3 任务与结果

数值任务继续进入 `ProcessingController`、现有工作线程、取消令牌和 `ResultRouter`。STFT/CWT、寿命热图的 CPU/CUDA 规划沿用当前计算框架。当前界面的逐帧 FFT 使用 NumPy，区域拟合、普通统计和旧领域算法的后端按各自真实实现标识。

菜单展开、定位参数和展示输入时只做准备。计算任务记录中包含算法动作 ID、真实输入身份和参数，便于比较菜单与左面板是否提交了同一项工作。原有曲线工具的结果先沿用绘图区状态，若以后增加可恢复曲线分析结果，再扩展其数据模型。

## 5. 首版接入需要处理的确定问题

| 问题 | 源码证据与处理要求 |
| --- | --- |
| 寿命模型控件被覆盖 | `setup_fs_GROUP()` 在约 845、925 行两次赋值 `self.model_combo`，执行槽读到后建控件。改为明确的页面控件或共享模型状态，并同步“单指数 / 双指数”文案与已有多输出能力 |
| 双指数传热的寿命来源 | 当前双指数主结果为 `tau1_map`，切换热图显示字段只改变 `active_result_field`。准备页显式展示主寿命 tau1 作为换算源，后续扩展 tau2 时传递明确的字段引用 |
| 分析页与导入页耦合 | `signal_connect()` / `between_stack_change()` 将 `fuction_select` 与导入、分析页和时空控件绑定，进入超快模式还强制 `FS_mode_combo=1`。新增独立分析导航，按目标页定位，避免重置覆盖菜单选择 |
| 高级操作中的坏帧异步返回错误 | `BadFrameDialog.get_bad_frames()` 读取 `data.origin` 并把 `signal.emit()` 返回值当结果。作为高级操作专项修复，补检测结果信号、修复完成/失败信号，并在真正完成后报告结果。明确当前 Data 的修改语义和可接受 dtype |
| 两条 ROI 均值语义不同 | `easy_process()` 把 ROI 外置零再除以全图像素数，Anchor 统计则除以 ROI 内有效像素数。菜单“ROI 时序统计”使用明确的区域统计定义，原路径按用途命名或修正并增加数值回归。整数输入的均值、标准差等应核对浮点输出，避免统计结果截断 |
| 时间平均图名称与输入 | `accumulate_amplitude()` 实际取 mean，当前入口还允许 HW。统一“时间平均振幅图”命名并校验 T 轴，避免对二维图的高度求均值后误称振幅图 |
| 单帧 FFT/IFFT 的轴处理 | FFT 的 HW 分支仍读取 `pure_data[i]`，IFFT 用 `atleast_3d(HW)` 产生 HW1 后按 THW 理解。实施时补 HW、1HW、THW 与复频谱往返测试 |
| 曲线峰面积 API 不兼容 | `_update_peak_analysis()` 使用 `np.trapz`。核查固定 NumPy 2.5.4 环境已缺少该 API，`np.trapezoid` 可用。同步验证基线、面积、FWHM 与短曲线边界 |
| 曲线 PSD 输入与单位 | `_apply_psd()` 由平均时间间隔推导采样率，当前转换覆盖 ms/us/μs/ns。核对 s/ps/fs、非均匀或非递增时间、非有限值与实际幅值单位，明确拒绝或换算策略 |
| 曲线模式与峰开关状态 | 现有 PSD/Histogram 隐藏峰工具时未清除勾选，开启峰工具恢复时域时未同步互斥组选中态。共享 QAction 的同时修复完整状态迁移，并区分预计算直方图与合法时序输入 |
| 扩散缺少前置检查 | `vectorROI_selection()` 在确认 `vector_array` 前读取其 shape，最终方差拟合在展示方法内。补来源、有效线 ROI、至少两个有效拟合时刻和拟合失败检查 |
| 光流输入与任务生命周期 | `clahe_and_blur()` 的 dtype 要求、FPS/空间尺度校验，以及整段数组分配、取消与结果提交需核查。新菜单在满足这些条件后开放执行 |

上述项目按所属菜单和算法分别验收。高级操作的坏帧问题作为该编辑功能的专项修复追踪。新增分析菜单按其实际入口逐项完成接入条件，公共导航与其它成熟算法可以并行推进。

## 7. 实施顺序与验收

4. 核对菜单与左面板的参数、数据源、任务记录及结果一致性。补充使用说明、交接文档和对应验收记录。版本号由该轮发布范围确定。
